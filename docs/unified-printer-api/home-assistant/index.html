THE IDEA

PrintDeck translates.
Home Assistant reacts.

The PrintDeck integration discovers compatible devices, asks for the Unified API token in the Home Assistant interface and creates the available printer entities automatically.

01

Finished print

Turn on a lamp, send a phone notification or announce that the part is ready.

02

Progress milestones

React when progress crosses 25%, 50% or 75% to change an indicator light or update a dashboard.

03

Job paused or stopped

React to paused, failed or cancelled jobs before returning to the workshop.

04

Workshop overview

Show connection, temperatures, remaining time and the current layer on one local dashboard.

NATIVE HOME ASSISTANT EXPERIENCE

No configuration.yaml.
Set it up in the interface.

Install the maintained PrintDeck custom integration through HACS. It uses the normal Home Assistant Devices & services flow; HACS is only the installation method.

  1. 01

    Enable the API

    Open Web Config on PrintDeck, choose Unified Printer API, enable it and copy the generated access token.

  2. 02

    Install through HACS

    Add the PrintDeck repository as a custom Integration repository in HACS, download PrintDeck and restart Home Assistant.

    Open the PrintDeck repository
  3. 03

    Add PrintDeck

    Open Settings > Devices & services > Add integration. Choose a discovered PrintDeck or search for PrintDeck, then enter the Unified API token.

  4. 04

    Import an automation blueprint

    Choose a ready-made automation and select your PrintDeck sensor and light in the Home Assistant interface.

    Light when a print finishes Lights at 25%, 50% and 75%
MANUAL REST FALLBACK

Prefer YAML?
Connect one state and one light.

This alternative setup does not require the PrintDeck integration. It watches one printer's phase and turns on one light entity through Home Assistant's REST sensor.

  1. 01

    Enable the API

    Open Web Config on PrintDeck, choose Unified Printer API, enable it and copy the generated access token.

  2. 02

    Find the printer ID

    Request the printer list and note the ID of the printer you want to watch.

    Terminal
    curl http://PRINTDECK-IP/v1/printers \
  -H 'Authorization: Bearer pd_your_token_here'
  3. 03

    Keep the token in secrets.yaml

    Include the word Bearer in the secret value.

    secrets.yaml
    printdeck_api_bearer: "Bearer pd_your_token_here"
  4. 04

    Add the phase sensor

    This makes one request every 10 seconds. Change PRINTDECK-IP and printer ID 1 in the URL.

    configuration.yaml
    rest:
  - resource: "http://PRINTDECK-IP/v1/printers/1/status"
    method: GET
    headers:
      Authorization: !secret printdeck_api_bearer
    scan_interval: 10
    timeout: 5
    sensor:
      - name: "PrintDeck Phase"
        unique_id: printdeck_printer_1_phase
        value_template: "{{ value_json.status.job.phase }}"
  5. 05

    Check and restart Home Assistant

    Validate the YAML in Developer Tools, restart Home Assistant, then confirm that the PrintDeck Phase entity has a value.

  6. 06

    Add the automation

    Replace light.living_room with the entity ID of your lamp.

    automations.yaml
    - alias: "PrintDeck - light on when print completes"
  id: printdeck_light_on_when_print_completes
  triggers:
    - trigger: state
      entity_id: sensor.printdeck_phase
      to: "completed"
  conditions:
    - condition: template
      value_template: >-
        {{ trigger.from_state is not none and
           trigger.from_state.state in ['preparing', 'printing', 'paused'] }}
  actions:
    - action: light.turn_on
      target:
        entity_id: light.living_room
  mode: single
  7. 07

    Run a short test print

    Watch the phase entity move to completed. If the lamp does not switch on, open the automation trace to see the trigger and condition results.

ALL NORMALIZED STATES

Use broad phases
or detailed activities.

Job phase is best for most automations. Job activity exposes the detailed activities that drive PrintDeck reactions when the printer reports them.

Job phases

Every supported job phase value:

unknownidlepreparingprintingpausedcompletedfailedcancelled

Detailed activities

Every supported job activity value:

unknownstandbypreparingnozzle_heatingbed_heatinghomingbed_levelingnozzle_cleaningcalibratingfilament_changingfilament_unloadingfilament_loadingfilament_purgingprintingpausedcompletedfailedcancelled

You do not need one entity per value. The PrintDeck Activity sensor below moves between every listed activity, and an automation can react to the value you choose.

Connection and status values

connection.state
stopped waiting_for_network connecting online offline
connection.reachability
unknown online offline
connection.detail_level
summary full
job.kind
print calibration

Detailed activity availability depends on what the connected printer reports. The API value unknown uses PrintDeck's unavailable reaction as its fallback. A selected printer provides full live data; other saved printers may provide summary data at the configured Printer List Refresh interval.

COMPLETE STATUS SENSOR PACK

One API request.
Every detailed-status field.

Use this block instead of the smaller phase-only block above. It creates entities for every field returned by the detailed status endpoint while still polling PrintDeck only once per interval.

configuration.yaml
rest:
  - resource: "http://PRINTDECK-IP/v1/printers/1/status"
    method: GET
    headers:
      Authorization: !secret printdeck_api_bearer
    scan_interval: 10
    timeout: 5
    sensor:
      - name: "PrintDeck Printer ID"
        unique_id: printdeck_printer_1_id
        value_template: "{{ value_json.status.printer_id }}"

      - name: "PrintDeck Connection"
        unique_id: printdeck_printer_1_connection
        value_template: "{{ value_json.status.connection.state }}"

      - name: "PrintDeck Reachability"
        unique_id: printdeck_printer_1_reachability
        value_template: "{{ value_json.status.connection.reachability }}"

      - name: "PrintDeck Detail Level"
        unique_id: printdeck_printer_1_detail_level
        value_template: "{{ value_json.status.connection.detail_level }}"

      - name: "PrintDeck Update Marker"
        unique_id: printdeck_printer_1_updated_at_ms
        value_template: "{{ value_json.status.connection.updated_at_ms }}"
        unit_of_measurement: "ms"

      - name: "PrintDeck Phase"
        unique_id: printdeck_printer_1_phase
        value_template: "{{ value_json.status.job.phase }}"

      - name: "PrintDeck Job Kind"
        unique_id: printdeck_printer_1_job_kind
        value_template: "{{ value_json.status.job.kind }}"

      - name: "PrintDeck Activity"
        unique_id: printdeck_printer_1_activity
        value_template: "{{ value_json.status.job.activity }}"

      - name: "PrintDeck Job Name"
        unique_id: printdeck_printer_1_job_name
        value_template: "{{ value_json.status.job.name | default('none', true) }}"

      - name: "PrintDeck Progress"
        unique_id: printdeck_printer_1_progress
        value_template: "{{ value_json.status.job.progress_percent }}"
        availability: >-
          {{ value_json.status.connection.detail_level == 'full' and
             not value_json.status.connection.stale }}
        unit_of_measurement: "%"

      - name: "PrintDeck Elapsed"
        unique_id: printdeck_printer_1_elapsed
        value_template: "{{ value_json.status.job.elapsed_seconds }}"
        availability: >-
          {{ value_json.status.connection.detail_level == 'full' and
             not value_json.status.connection.stale }}
        device_class: duration
        unit_of_measurement: "s"

      - name: "PrintDeck Remaining"
        unique_id: printdeck_printer_1_remaining
        value_template: "{{ value_json.status.job.remaining_seconds }}"
        availability: "{{ not value_json.status.connection.stale }}"
        device_class: duration
        unit_of_measurement: "s"

      - name: "PrintDeck Current Layer"
        unique_id: printdeck_printer_1_current_layer
        value_template: "{{ value_json.status.job.current_layer }}"
        availability: >-
          {{ value_json.status.connection.detail_level == 'full' and
             not value_json.status.connection.stale }}

      - name: "PrintDeck Total Layers"
        unique_id: printdeck_printer_1_total_layers
        value_template: "{{ value_json.status.job.total_layers }}"
        availability: >-
          {{ value_json.status.connection.detail_level == 'full' and
             not value_json.status.connection.stale }}

      - name: "PrintDeck Nozzle Temperature"
        unique_id: printdeck_printer_1_nozzle_temperature
        value_template: "{{ value_json.status.temperatures.nozzle_current_c }}"
        availability: >-
          {{ value_json.status.temperatures.nozzle_current_c is not none and
             not value_json.status.connection.stale }}
        device_class: temperature
        state_class: measurement
        unit_of_measurement: "°C"

      - name: "PrintDeck Nozzle Target"
        unique_id: printdeck_printer_1_nozzle_target
        value_template: "{{ value_json.status.temperatures.nozzle_target_c }}"
        availability: >-
          {{ value_json.status.temperatures.nozzle_target_c is not none and

        device_class: temperature
        unit_of_measurement: "°C"

        device_class: temperature
        state_class: measurement
        unit_of_measurement: "°C"

Before you restart

Keep the matching token in secrets.yaml, replace PRINTDECK-IP and printer ID 1. If configuration.yaml already has a top-level rest section, add this resource below it instead of creating a second rest key.

GOOD TO KNOW

Local by design.
Read-only by design.

Home Assistant polls PrintDeck; PrintDeck does not send webhooks. Keep both devices on a trusted local network and do not expose the API port to the internet. The integration stores its token in the Home Assistant config entry; manual REST setups should keep it in secrets.yaml.

Progress, temperatures and reaction-level activities are fullest for the printer currently selected on PrintDeck. Connection and summary job state remain useful for other saved printers.
