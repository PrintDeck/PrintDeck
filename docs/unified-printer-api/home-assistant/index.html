Open the official HACS installation guide
  1. 01

    Enable the API in PrintDeck

    Open PrintDeck Web Config, choose Settings > Unified Printer API, enable it and copy the generated token. Keep it private; you will paste the raw token into Home Assistant without adding the word Bearer.

  2. 02

    Add PrintDeck to HACS

    Use the button below. It opens the PrintDeck custom repository directly in HACS. If the button cannot reach your Home Assistant, use the manual path shown underneath.

    Open PrintDeck in HACS
    Add the repository manually

    Open HACS > Integrations > three-dot menu > Custom repositories. Paste https://github.com/PrintDeck/home-assistant, choose Integration as the type, then select Add.

    Read the official HACS custom repository guide
  3. 03

    Download and restart

    In HACS, select PrintDeck, choose Download and install the newest version. Restart Home Assistant when HACS asks. Refreshing the browser is not a restart.

  4. 04

    Add the integration

    Open Settings > Devices & services > Add integration and search for PrintDeck. Choose a discovered monitor, or enter printdeck.local or its local IP address. Paste the raw Unified API token and submit.

    Add PrintDeck to Home Assistant
  5. 05

    Name and assign

    Home Assistant shows the PrintDeck monitor and every configured printer. Rename them or assign areas if useful, then choose Finish. Use Add hub only when you have another physical PrintDeck monitor.

  6. 06

    Confirm the entities

    Open the PrintDeck integration. You should see one hub and a device for every printer. Each printer exposes progress, phase, activity, temperatures, layers, time, connection data, network address and network port when available.

    Printers stay synchronized automatically

    Add a printer in PrintDeck and Home Assistant creates its device and entities after the next polling cycle. Remove a printer and integration version 0.1.2 or newer removes its Home Assistant device and entities after the next complete refresh. A temporary connection problem never triggers cleanup. Deleting a printer intentionally breaks automations that reference its entities; edit the saved printer instead if only its address changed.

YOUR FIRST AUTOMATION

Turn on one light
when progress reaches 75%.

This example uses the visual automation editor. It works with any percentage, including 82% or 88%.

  1. WHEN

    Choose Numeric state, select the printer's Print progress entity and set Above to 74.9.

  2. AND IF

    Choose State, select the same printer's Print phase entity and set the state to Printing.

  3. THEN DO

    Choose Light: Turn on and select one light. Use Turn on rather than Toggle so the result is predictable.

  4. SAVE

    Give the automation a name and save it. Run actions tests only the light; a short print tests the trigger and condition.

Why 74.9 instead of 75?

Home Assistant's Above test is strict. A threshold of 74.9 triggers when the sensor first reports 75 or any higher value. The Printing condition prevents an old stored progress value from turning on the light while the printer is idle.

If something does not appear,
check these first.

PrintDeck is missing from Add integration

Confirm that HACS downloaded it, restart Home Assistant and refresh the browser after the restart.

Home Assistant asks for a firmware update

Update the PrintDeck monitor, then try the connection again. This message means the monitor does not yet advertise native integration support.

Cannot connect to the host

Keep Home Assistant and PrintDeck on the same local network. If printdeck.local does not resolve, enter the local IP shown by PrintDeck.

The token is rejected

Copy a fresh token from PrintDeck Web Config and paste it exactly. Do not add Bearer in the native integration form.

Progress is unavailable

Select that printer on PrintDeck so it has a full live connection. Some inactive printers expose only summary data.

The light did not turn on

Open the automation and choose Traces. The trace shows whether the progress trigger fired and whether the Printing condition passed.

MANUAL REST FALLBACK

Prefer YAML?
Connect one state and one light.

The native integration above is recommended. Open this advanced fallback only when HACS cannot be used or you deliberately want to maintain the REST sensors yourself.

Show the manual REST instructions
  1. 01

    Enable the API

    Open Web Config on PrintDeck, choose Unified Printer API, enable it and copy the generated access token.

  2. 02

    Find the printer ID

    Request the printer list and note the ID of the printer you want to watch.

    Terminal
    curl http://PRINTDECK-IP/v1/printers \
  -H 'Authorization: Bearer pd_your_token_here'
  3. 03

    Keep the token in secrets.yaml

    Include the word Bearer in the secret value.

    secrets.yaml
    printdeck_api_bearer: "Bearer pd_your_token_here"
  4. 04

    Add the phase sensor

    This makes one request every 10 seconds. Change PRINTDECK-IP and printer ID 1 in the URL.

    configuration.yaml
    rest:
  - resource: "http://PRINTDECK-IP/v1/printers/1/status"
    method: GET
    headers:
      Authorization: !secret printdeck_api_bearer
    scan_interval: 10
    timeout: 5
    sensor:
      - name: "PrintDeck Phase"
        unique_id: printdeck_printer_1_phase
        value_template: "{{ value_json.status.job.phase }}"
  5. 05

    Check and restart Home Assistant

    Validate the YAML in Developer Tools, restart Home Assistant, then confirm that the PrintDeck Phase entity has a value.

  6. 06

    Add the automation

    Replace light.living_room with the entity ID of your lamp.

    automations.yaml
    - alias: "PrintDeck - light on when print completes"
  id: printdeck_light_on_when_print_completes
  triggers:
    - trigger: state
      entity_id: sensor.printdeck_phase
      to: "completed"
  conditions:
    - condition: template
      value_template: >-
        {{ trigger.from_state is not none and
           trigger.from_state.state in ['preparing', 'printing', 'paused'] }}
  actions:
    - action: light.turn_on
      target:
        entity_id: light.living_room
  mode: single
  7. 07

    Run a short test print

    Watch the phase entity move to completed. If the lamp does not switch on, open the automation trace to see the trigger and condition results.

ALL NORMALIZED STATES

Use broad phases
or detailed activities.

Job phase is best for most automations. Job activity exposes the detailed activities that drive PrintDeck reactions when the printer reports them.

Job phases

Every supported job phase value:

unknownidlepreparingprintingpausedcompletedfailedcancelled

Detailed activities

Every supported job activity value:

unknownstandbypreparingnozzle_heatingbed_heatinghomingbed_levelingnozzle_cleaningcalibratingfilament_changingfilament_unloadingfilament_loadingfilament_purgingprintingpausedcompletedfailedcancelled

You do not need one entity per value. The PrintDeck Activity sensor below moves between every listed activity, and an automation can react to the value you choose.

Connection and status values

connection.state
stopped waiting_for_network connecting online offline
connection.reachability
unknown online offline
connection.detail_level
summary full
job.kind
print calibration

Detailed activity availability depends on what the connected printer reports. The API value unknown uses PrintDeck's unavailable reaction as its fallback. A selected printer provides full live data; other saved printers may provide summary data at the configured Printer List Refresh interval.

    method: GET
    headers:
      Authorization: !secret printdeck_api_bearer
    scan_interval: 10
    timeout: 5

        unique_id: printdeck_printer_1_id
        value_template: "{{ value_json.status.printer_id }}"

        unique_id: printdeck_printer_1_connection
        value_template: "{{ value_json.status.connection.state }}"

      - name: "PrintDeck Reachability"

        value_template: "{{ value_json.status.connection.reachability }}"

      - name: "PrintDeck Update Marker"
        unique_id: printdeck_printer_1_updated_at_ms

        value_template: "{{ value_json.status.job.phase }}"

        value_template: "{{ value_json.status.job.kind }}"

      - name: "PrintDeck Activity"

Before you restart

Keep the matching token in secrets.yaml, replace PRINTDECK-IP and printer ID 1. If configuration.yaml already has a top-level rest section, add this resource below it instead of creating a second rest key.

GOOD TO KNOW

Local by design.
Read-only by design.

Home Assistant polls PrintDeck; PrintDeck does not send webhooks. Keep both devices on a trusted local network and do not expose the API port to the internet. The integration stores its token in the Home Assistant config entry; manual REST setups should keep it in secrets.yaml.

Progress, temperatures and reaction-level activities are fullest for the printer currently selected on PrintDeck. Connection and summary job state remain useful for other saved printers.
