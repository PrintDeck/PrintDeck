# PrintDeck security policy

## Supported versions

Security fixes are provided for the latest stable PrintDeck release. Before
reporting a vulnerability, confirm whether it is still present in that release
when it is safe to do so.

## Reporting a vulnerability

Do not disclose a suspected vulnerability in a public GitHub issue,
discussion, screenshot or log.

Use
[GitHub private vulnerability reporting](https://github.com/PrintDeck/PrintDeck/security/advisories/new)
to send the report privately. If private reporting is unavailable, use the
[PrintDeck Support page](https://printdeck.xyz/support/) to
request a private contact channel without including vulnerability details.

Include, when available:

- the affected PrintDeck version and hardware variant;
- a concise description of the issue and its potential impact;
- reproducible steps or a minimal proof of concept;
- any conditions required to reproduce it;
- a suggested mitigation, if known.

Remove credentials, tokens, access codes, printer serial numbers, addresses,
SSIDs and private job data unless a specific value is essential to the report.
Never use credentials or devices belonging to another person.

Relevant reports include credential exposure, unauthorized access, unsafe OTA
behavior, certificate-validation failures, Web Config vulnerabilities and
unexpected exposure of local printer or camera data.

Please allow time to validate and correct a report before public disclosure.
Receipt of a report does not guarantee a particular response or release
timeline.
